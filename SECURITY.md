# Security Policy

## Supported versions

Security fixes are considered for the current version represented by the repository's default branch. Older versions may not receive fixes.

## Reporting a vulnerability

Please report suspected security vulnerabilities privately to the project maintainer through GitHub's private vulnerability reporting feature, if it is enabled for this repository. If that feature is unavailable, contact the maintainer through a private GitHub channel rather than posting exploit details publicly.

Include, where possible:

- A short description of the issue and its potential impact.
- The affected file, component, version, or commit.
- Reproduction steps that do not expose real users' data.
- Any suggested mitigation.

Please allow time for investigation before publicly disclosing an unpatched vulnerability. Do not access, alter, or delete data that does not belong to you.

## Protecting secrets

- Never commit passwords, access tokens, private keys, signing keystores, keystore passwords, or production credentials.
- Keep local configuration and secrets out of Git.
- Rotate a secret immediately if it has been exposed.
- Use test credentials and avoid placing sensitive user data in logs, screenshots, issues, or pull requests.

## Scope and limitations

This policy describes how to report issues; it is not a guarantee that every report can be fixed or that every version is free of vulnerabilities. Please verify the security of the version you install and keep your device and dependencies updated.
